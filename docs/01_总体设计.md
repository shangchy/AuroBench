# 大模型搭建及验证 — 总体设计

> 覆盖「本地小模型 → 云 DeepSeek 大模型 → 云多满血大模型」三阶段，及「脚本评测 + AI 应用/Agent 评测」双评测体系的总体架构设计。

## 1. 项目概述

### 1.1 背景

针对中国产高性能大模型（DeepSeek 等），从**功能**与**成本**两个维度验证其可用性，为是否导入、以何种形态（SaaS / 本地 / 云）导入提供决策依据。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 方法论建立 | 建立可复现的「脚本 + Agent」双通道评测体系 |
| 能力验证 | 判定中国产大模型的功能满足度与质量差距 |
| 成本测算 | 量化云上满血大模型的 TCO，支撑投资决策 |
| 导入建议 | 输出推荐模型、部署形态与导入路线图 |

### 1.3 范围（三阶段）

| 阶段 | 名称 | 对象 | 环境 |
|------|------|------|------|
| 一 | 本地小模型搭建及评测 | 8 个开源小模型 | 本地（ollama，CPU） |
| 二 | 云环境搭建 DeepSeek 大模型 | DeepSeek v4（满血版） | 云（阿里/腾讯/华为） |
| 三 | 多个满血大模型横向对比 | DeepSeek v4、Qwen 3.8、GLM 5.3（满血版） | 云 |

## 2. 三阶段总体设计

### 2.1 阶段一：本地小模型搭建及评测

- **目标**：小成本跑通评测方法论，验证脚本评测与 Agent 评测可行性，输出初步基准。
- **内容**：
  - ollama 本地部署 8 个开源小模型（qwen2.5 1.5b/3b/7b、deepseek-r1:1.5b、llama3.2:3b、gemma2:2b、glm4:9b、Seed-Coder-8B）
  - 脚本评测框架搭建（规则 + LLM 裁判）
  - 通用 Agent 评测框架初版（RAG + 工具调用）
  - vLLM 部署 POC（阶段一末预演，沉淀部署资产供云阶段复用）
- **产出**：评测方法论、脚本评测框架、初步对比报告、Agent 评测框架 v0、vLLM 部署脚本与对接验证。

### 2.2 阶段二：云环境搭建 DeepSeek 大模型

- **目标**：在云上部署 DeepSeek v4 满血版，完成单模型深度评测。
- **内容**：
  - 云资源申请与 GPU 环境构建
  - DeepSeek v4 满血部署（推理服务）
  - 脚本评测全量执行 + Agent 评测（通用 + Smartrans）
  - 成本实测
- **产出**：DeepSeek v4 单模型完整评测报告、成本数据、Agent 评测基线。

### 2.3 阶段三：多个满血大模型横向对比

- **目标**：DeepSeek v4、Qwen 3.8、GLM 5.3 满血版横向对比，输出结论。
- **内容**：
  - 多模型云环境构建（统一推理接口）
  - 统一题集与统一 Agent 任务的横向执行
  - 性能 / 质量 / 成本三维对比
  - 结论与导入建议
- **产出**：多模型对比矩阵、结论报告、导入路线图。

## 3. 总体架构

### 3.1 逻辑分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                        接入层                                 │
│   评测脚本 · AI 应用/Agent · 外部系统 · IDE(MCP 客户端)        │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                        评测层                                 │
│  ┌────────────────────┐    ┌──────────────────────────────┐  │
│  │   脚本评测引擎      │    │   Agent 评测引擎             │  │
│  │ 规则打分 · LLM 裁判 │    │  通用Agent · 业务Agent        │  │
│  └────────────────────┘    └──────────────────────────────┘  │
│            报告生成 · 对比矩阵 · 证据记录                      │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                     统一模型接入层                            │
│   LiteLLM 网关（OpenAI 兼容 · 路由 · 鉴权 · 限流 · 日志）      │
│   MCP Server（模型能力标准化为 MCP 工具）                     │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                      推理服务层                               │
│   本地：ollama(11434)     云：DeepSeek/Qwen/GLM 满血推理服务   │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 三阶段架构演进

**阶段一（本地）**

```
评测脚本 ──▶ ollama ──▶ 8 个小模型
Agent v0  ──▶ LiteLLM ──▶ ollama
```

**阶段二（云 DeepSeek 单模型）**

```
评测脚本 ──▶ LiteLLM 网关 ──▶ 云 DeepSeek v4 满血推理服务
Agent 评测 ──▶ MCP ──▶ LiteLLM ──▶ DeepSeek v4
```

**阶段三（云多满血模型）**

```
评测脚本 ──▶ LiteLLM 网关 ──┬─▶ DeepSeek v4
Agent 评测 ──▶ MCP ─────────┼─▶ Qwen 3.8
                            └─▶ GLM 5.3
```

### 3.3 本地架构（阶段一）

- 推理运行时：ollama（本地 HTTP 服务）
- 计算方式：CPU 推理
- 评测脚本：`scripts/eval/`（自动发现模型 + 断点续跑）

### 3.4 云架构（阶段二/三）

| 层 | 设计 |
|----|------|
| 推理服务 | 云厂商托管 API 或自建 vLLM 推理集群（GPU） |
| 统一入口 | LiteLLM 网关，屏蔽各厂商 API 差异 |
| 模型 | DeepSeek v4 / Qwen 3.8 / GLM 5.3 满血版 |
| 弹性 | 按需伸缩 GPU 实例，控制成本 |

**云平台选择**（阿里云百炼 / 腾讯云 / 华为云）：

| 平台 | 优势 | 适用 |
|------|------|------|
| 阿里云百炼 | 国产模型生态最全，DeepSeek/Qwen/GLM 均可用 | 首选 |
| 腾讯云 | 混元 + 生态，价格有竞争力 | 备选 |
| 华为云 | 昇腾国产算力，自主可控 | 信创场景 |

## 4. 评测体系设计（双评测方式）

评测采用「脚本评测 + AI 应用/Agent 评测」双通道互补，**详细评测方法、维度、打分公式与判定基准见《05 评测方法及打分规则》**。

| 方式 | 定位 | 关键指标 |
|------|------|----------|
| 脚本评测 | 客观量化基准 | 综合分（规则 + 裁判）、分维度分、耗时 |
| Agent 评测 | 真实场景验证 | 任务完成率、工具调用成功率、人工评分 |

- **脚本评测**：8 维度（推理/代码/问答/翻译/指令遵循/长文本/多轮对话/信息抽取）固定题集，规则 + LLM 裁判打分。
- **Agent 评测**：通用 Agent（RAG + 工具 + 多轮）+ Smartrans 业务场景，端到端指标 + 人工双盲评审。

评测指标覆盖功能（完成率/正确率）、质量（综合分/裁判分/人工评分）、性能（延迟/吞吐/并发）、成本（每 token/TCO）、稳定（可用性/错误率）五个层次。

## 5. 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 本地推理 | ollama | 统一本地运行时 |
| 云推理 | 云厂商托管 API / vLLM | 满血模型推理 |
| API 网关 | LiteLLM Proxy | OpenAI 兼容、路由、鉴权、限流、日志 |
| MCP | `mcp` (FastMCP) | 模型能力标准化为 MCP 工具，stdio + HTTP |
| 脚本评测 | Python + requests | 现有 `scripts/eval/` |
| Agent 框架 | 自研（RAG + 工具调用） | 统一评测载体 |

## 6. 数据与证据管理

- **证据规格**：统一记录测试用例 ID、输入、输出、评分、日志、时间戳、环境/模型版本。
- **可追溯性**：每条结果可回溯到具体题集/任务与执行环境。
- **版本管理**：模型版本、题集版本、Agent 版本全程记录，保证横向可比。

## 7. 安全、合规与护栏

### 7.1 数据与网络安全合规

- 云上数据合规：数据出境、隐私、许可审查（阶段二/三前置）。
- 密钥管理：云 API Key、LiteLLM master key 通过环境变量/密钥管理服务注入。
- 网络安全：网关默认内网绑定，对外加 TLS + 鉴权。

### 7.2 内容安全护栏（轻量自建，延后处理）

采用轻量护栏（敏感词/规则过滤 + 工具白名单，自建实现），覆盖四层：

| 层面 | 措施 |
|------|------|
| 输入护栏 | Prompt 注入检测、敏感词/越权指令识别、输入长度限制 |
| 输出护栏 | 有害内容关键词过滤、PII 模式匹配（手机号/身份证/邮箱）、违规内容拦截 |
| 数据护栏 | 评测数据脱敏（去标识化）、结果访问权限与留存策略 |
| 工具护栏 | Agent/MCP 工具白名单、参数校验、敏感操作二次确认 |

#### 7.2.1 敏感词库

分层词库（JSON 文件），按类别组织，支持关键词子串匹配与正则规则：

```json
{
  "政治敏感": ["..."],
  "色情暴力": ["..."],
  "违法违规": ["..."],
  "公司机密": ["项目代号", "客户名单"]
}
```

命中即拦截或标记；词库由专人定期维护更新。

#### 7.2.2 PII 识别规则

| 类型 | 正则 |
|------|------|
| 手机号 | `1[3-9]\d{9}` |
| 身份证 | `\d{17}[\dXx]` |
| 邮箱 | `[\w.-]+@[\w.-]+\.\w+` |
| 银行卡 | `\d{16,19}` |
| IPv4 | `\d{1,3}(\.\d{1,3}){3}` |

输出侧命中 PII 时拦截或脱敏替换（如 `138****8000`）。

#### 7.2.3 工具白名单

工具注册表定义允许调用的工具、参数 schema 与权限等级：

```json
{
  "allowed_tools": ["search", "translate", "calculator"],
  "sensitive_tools": ["db_write", "send_email"],
  "param_schema": { "search": { "query": "string" } }
}
```

`allowed_tools` 直接放行；`sensitive_tools` 需二次确认；白名单外工具一律拒绝。

## 8. 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 满血模型云成本超预算 | 项目超支 | 设预算告警、按需伸缩、先小规模验证 |
| 模型质量不达预期 | 结论不可用 | 扩大题集与 Agent 任务，人工双盲复核 |
| 评测标准化不足 | 结果不可比 | 冻结题集与基准，统一接入层 |
| 云平台 API 差异 | 接入成本高 | LiteLLM 网关统一屏蔽差异 |
