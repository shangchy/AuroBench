# LLM 对外服务设计文档（LiteLLM 网关 + MCP）

> 目标：在当前 ollama 本地推理环境之上，直接集成 **LiteLLM Proxy** 作为 OpenAI 兼容 API 网关，并新增 **MCP Server**，对外提供统一的模型调用与评测能力。
> 状态：设计稿，待确认后实施。

## 1. 目标与背景

当前架构只有 ollama 推理层（`localhost:11434`），缺乏对外统一入口。本设计新增两层：

1. **API 网关（LiteLLM Proxy）**：直接使用 LiteLLM 代理，提供 OpenAI 兼容统一入口，内置模型路由、鉴权（虚拟 Key）、限流、预算、fallback 与日志。
2. **MCP Server**：将模型能力封装为标准 MCP 工具，供 IDE / Agent 通过 stdio 或 HTTP 远程调用。

### 设计原则

- **直接集成 LiteLLM**：复用其成熟的网关能力，不自建重复轮子。
- **OpenAI 兼容**：上层调用方（OpenAI SDK、LangChain 等）零改造接入。
- **模型别名路由**：LiteLLM 配置层将对外别名映射到底层 ollama 模型。
- **双传输 MCP**：同一套工具定义，同时支持 stdio（本地）与 streamable HTTP（远程）。

## 2. 总体架构

```
                    ┌──────────────────────────────────┐
  外部系统 / 前端 ──▶│       LiteLLM Proxy (4000)       │
  (OpenAI SDK 等)  │  /v1/chat/completions · /v1/models │
                   │  /v1/embeddings · /ui 管理界面      │
                   │  鉴权 · 限流 · 预算 · fallback · 日志 │
                   └────────────────┬─────────────────┘
                                    │ ollama provider (api_base=11434)
  MCP 客户端 ─────▶ ┌───────────────▼─────────────────┐
  (IDE / Agent)    │        MCP Server (FastMCP)       │
  stdio · HTTP ───▶│  tools: chat / list_models /      │
                   │         generate / run_eval       │
                   └────────────────┬─────────────────┘
                                    │ 走 LiteLLM OpenAI 接口
                    ┌───────────────▼─────────────────┐
                    │     ollama 推理服务 (11434)       │
                    │  /api/generate · /api/tags       │
                    └─────────────────────────────────┘
```

## 3. 模块一：LiteLLM Proxy 集成

### 3.1 安装

```bash
pip install 'litellm[proxy]'
```

### 3.2 配置文件（接入 ollama）

```yaml
# litellm_config.yaml
model_list:
  - model_name: qwen-small          # 对外别名
    litellm_params:
      model: ollama_chat/qwen2.5:1.5b
      api_base: http://localhost:11434
  - model_name: qwen-mid
    litellm_params:
      model: ollama_chat/qwen2.5:3b
      api_base: http://localhost:11434
  - model_name: qwen-large
    litellm_params:
      model: ollama_chat/qwen2.5:7b
      api_base: http://localhost:11434
  - model_name: deepseek-r1
    litellm_params:
      model: ollama_chat/deepseek-r1:1.5b
      api_base: http://localhost:11434
  - model_name: llama3
    litellm_params:
      model: ollama_chat/llama3.2:3b
      api_base: http://localhost:11434
  - model_name: gemma2
    litellm_params:
      model: ollama_chat/gemma2:2b
      api_base: http://localhost:11434
  - model_name: text-embedding
    litellm_params:
      model: ollama/qwen3-embedding:0.6b
      api_base: http://localhost:11434

general_settings:
  master_key: sk-your-master-key   # 主密钥，网关鉴权用
```

### 3.3 端点（LiteLLM 自带，OpenAI 兼容）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/v1/chat/completions` | POST | 对话补全 |
| `/v1/completions` | POST | 文本补全 |
| `/v1/embeddings` | POST | 向量化 |
| `/v1/models` | GET | 列出配置的模型 |
| `/health/liveliness` | GET | 健康检查 |
| `/ui` | GET | 管理界面（密钥、用量、日志） |

### 3.4 鉴权（虚拟 Key）

LiteLLM 内置虚拟 Key 机制，可为不同调用方签发独立 Key：

```bash
# 生成虚拟 Key（可设预算、限流、允许的模型）
litellm generate key --models qwen-mid,qwen-small --max_budget 100 --rpm_limit 60
```

调用方携带 `Authorization: Bearer <key>` 即可。

### 3.5 内置能力（直接复用）

- **限流**：`--rpm_limit`（每分钟请求数）、`--tpm_limit`（每分钟 token）
- **预算**：`--max_budget`（按 Key 限额）
- **fallback / 重试**：`litellm_params.fallback`
- **日志**：请求/响应/token 用量结构化落盘

### 3.6 启动

```bash
litellm --config litellm_config.yaml --port 4000
```

## 4. 模块二：MCP Server

### 4.1 工具定义

| 工具 | 参数 | 说明 |
|------|------|------|
| `chat` | `prompt`, `model?` | 单轮对话（走 LiteLLM 网关） |
| `list_models` | — | 枚举可用模型 |
| `generate` | `prompt`, `model?` | 原始补全 |
| `run_eval` | `models?`, `dimensions?` | 触发评测，返回报告摘要 |

### 4.2 双传输实现

MCP Server 统一走 LiteLLM 网关的 OpenAI 接口（`http://localhost:4000/v1/chat/completions`），避免直接依赖 ollama：

```python
# mcp/server.py
from mcp.server.fastmcp import FastMCP
from openai import OpenAI

mcp = FastMCP("llm-gateway")
client = OpenAI(base_url="http://localhost:4000/v1", api_key="sk-your-master-key")

@mcp.tool()
async def chat(prompt: str, model: str = "qwen-mid") -> str:
    r = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
    )
    return r.choices[0].message.content

@mcp.tool()
async def list_models() -> list[str]:
    return [m.id for m in client.models.list().data]

@mcp.tool()
async def run_eval(models: list[str] | None = None) -> dict:
    ...  # 复用 scripts/eval，返回报告摘要

# stdio：python mcp/server.py
# HTTP：mcp.run(transport="streamable-http", host="0.0.0.0", port=8000)
```

## 7. 安全考虑

- `master_key` 与虚拟 Key 通过环境变量注入，不进版本库。
- LiteLLM 网关默认绑定 `127.0.0.1`，对外暴露时改绑 `0.0.0.0` 并启用 Key 鉴权。
- MCP HTTP 模式建议加反向代理 + TLS（如 Caddy/Nginx）。
