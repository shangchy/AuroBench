# LLM 评测环境 — 用户操作手册

> 适用对象：需要在 Windows 机器上一键部署 LLM 评测环境并运行模型评测的用户。

## 1. 概述

本套件用于在本地部署开源大模型，并通过自研评测脚本对多个模型进行**功能对比验证**。

核心能力：

- 一键部署：`ollama` + 模型 + 评测脚本 + Python 依赖
- 自动评测：生成回答 → 规则打分 + LLM 裁判打分 → 输出对比报告
- 模型存储：通过 `OLLAMA_MODELS` 指定目录（默认非系统盘）

## 2. 目录结构

```
项目根目录
├── deploy\
│   ├── setup.bat        # 一键部署入口（双击运行）
│   └── setup.ps1        # 部署逻辑脚本
├── scripts\
│   └── eval\
│       ├── config.py    # 配置（模型列表、参数、路径）
│       ├── questions.py # 评测题集（8 个维度）
│       ├── runner.py    # 调用模型生成回答
│       ├── scorer.py    # 规则 + LLM 裁判打分
│       ├── report.py    # 生成报告
│       ├── main.py      # 入口：生成 → 打分 → 报告
│       └── results\     # 运行产物（自动生成）
└── docs\                # 文档
```

## 3. 环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | Windows 10/11 |
| Python | 3.10+（需加入 PATH） |
| 网络 | 首次部署需联网下载 ollama 与模型（约 13GB） |
| 磁盘 | 预留 ≥ 20GB 空间（建议非系统盘） |
| GPU | 可选；无 GPU 则用 CPU 推理（7B 模型较慢） |

## 4. 快速开始（一键部署）

### 4.1 分发内容

将以下内容拷贝到目标机器（**保持目录关系**）：

```
deploy\
scripts\eval\
```

### 4.2 执行部署

双击 `deploy\setup.bat`，脚本自动完成：

1. 检测硬件（GPU / CPU）
2. 安装 Ollama（已装则跳过，否则走 `winget`）
3. 配置模型存储目录（写入用户级环境变量 `OLLAMA_MODELS`）
4. 启动 `ollama serve` 服务
5. 拉取模型（已存在自动跳过）
6. 安装 Python 依赖（`requests`）
7. 部署评测脚本到 `%USERPROFILE%\llm-eval\`

> 若 PowerShell 执行策略拦截，可右键 `setup.bat` → 以管理员身份运行；脚本已内置 `-ExecutionPolicy Bypass`。

## 5. 运行评测

部署完成后，评测脚本位于 `%USERPROFILE%\llm-eval\`：

```bat
cd %USERPROFILE%\llm-eval
python main.py
```

脚本按三步自动执行：

1. **生成回答** — 对每个候选模型 × 每道题调用 ollama 生成结果
2. **打分** — 规则匹配 + LLM 裁判（`qwen2.5:7b`）双通道打分
3. **生成报告** — 输出 `report.md` 与 `report.csv`

**断点续跑**：脚本支持中途中断后重跑，已完成的题目会自动跳过，无需重头开始。

## 6. 查看评测报告

报告输出在 `%USERPROFILE%\llm-eval\results\`：

| 文件 | 说明 |
|------|------|
| `report.md` | 汇总报告（总体排名、分维度平均分、逐题明细） |
| `report.csv` | 逐题明细表（可用 Excel 打开） |
| `raw_results.json` | 模型原始回答 |
| `scores.json` | 打分结果 |

## 7. 模型管理

### 7.1 查看已安装模型

```bat
ollama list
```

### 7.2 新增模型

```bat
ollama pull <模型名:版本>
```

示例：`ollama pull qwen2.5:3b`

### 7.3 删除模型

```bat
ollama rm <模型名:版本>
```

### 7.4 模型存储位置

- 通过环境变量 `OLLAMA_MODELS` 指定模型存储目录；修改后需**注销重新登录**生效。

## 8. 配置说明（`config.py`）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `AUTO_DISCOVER_MODELS` | `True` | 自动发现 ollama 中所有生成模型参与评测 |
| `EXCLUDE_KEYWORDS` | `["embedding", "embed"]` | 自动排除的模型（按名称关键词） |
| `CANDIDATE_MODELS` | 8 个模型 | 当关闭自动发现时的手动模型清单 |
| `JUDGE_MODEL` | `qwen2.5:7b` | 用作裁判打分的模型 |
| `GEN_PARAMS` | temperature=0.2 | 生成参数（温度、采样、最大 token） |
| `JUDGE_PARAMS` | temperature=0.0 | 裁判参数 |
| `TIMEOUT` | 900 | 单次请求超时（秒） |

评测维度、题集结构与打分规则的详细说明见《05 评测方法及打分规则》。

## 9. 常见问题（FAQ）

**Q1：双击 setup.bat 没反应或报错？**
右键以管理员身份运行；确认目标机器能联网访问 `https://ollama.com`。

**Q2：模型下载很慢？**
模型合计约 13GB，网速决定时长。可改为在内网/离线环境使用 `OLLAMA_MODELS` 直接拷贝模型目录。

**Q3：`python main.py` 报连接错误？**
确认 ollama 服务已启动：执行 `ollama list` 有输出即为正常；否则运行 `ollama serve`。

**Q4：运行中 CPU 占用高/速度慢？**
无 GPU 环境下 7B 模型推理较慢属正常；可只保留小模型（1.5b/2b/3b）评测。

**Q5：想评测全部模型但只跑了一部分？**
检查 `config.py` 的 `AUTO_DISCOVER_MODELS` 是否为 `True`；确认目标模型已 `ollama pull`。

**Q6：如何更换裁判模型？**
修改 `config.py` 的 `JUDGE_MODEL`，例如改为 `deepseek-r1:1.5b`。
