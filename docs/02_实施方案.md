# 大模型搭建及验证 — 实施方案

> 说明「怎么做」：三阶段的具体实施方法与双评测（脚本 + AI 应用/Agent）的操作方法、判定基准、环境方案与成本测算。

## 1. 实施总则

- **基准先行**：先冻结判定基准与题集，再执行评测，保证横向可比。
- **小步验证**：本地小模型跑通方法论后，再上云本格验证，控制成本。
- **双通道评测**：脚本评测（客观量化）+ Agent 评测（真实场景），互补判定。
- **统一接入**：所有模型经 LiteLLM 网关统一调用，屏蔽环境差异。
- **轻量护栏**：输入/输出敏感词过滤 + 工具白名单，自建实现（设计见 01 第 7.2 节）。

## 2. 阶段一实施方案：本地小模型搭建及评测

### 2.1 环境搭建

| 步骤 | 操作 |
|------|------|
| 1 | 安装 ollama（`winget install Ollama.Ollama`） |
| 2 | 拉取 6 个小模型（qwen2.5 1.5b/3b/7b、deepseek-r1:1.5b、llama3.2:3b、gemma2:2b） |
| 3 | 部署脚本评测框架 `scripts/eval/` |

### 2.2 脚本评测

- 运行 `python main.py`，8 维度 24 题，规则 + LLM 裁判打分。
- 输出 `report.md` / `report.csv`，形成初步对比基准。

### 2.3 Agent 评测 v0

- 搭建通用 Agent 框架初版（RAG + 工具调用 + 多轮），接入本地小模型跑通流程。
- 验证 Agent 评测的指标采集（任务完成率、工具调用成功率）。

### 2.4 vLLM 部署 POC（阶段一末预演）

为避免阶段二/三重复搭建，阶段一末用 vLLM 部署 1 个小模型做部署预演：

- **目的**：提前沉淀可复用的 vLLM 部署脚本、模型权重准备与参数配置。
- **内容**：vLLM 部署 1 个小模型 → 经 LiteLLM 网关接入 → 用评测脚本跑通验证。
- **产出**：vLLM 部署脚本、LiteLLM 对接配置、对接验证报告。

> 说明：阶段一小模型评测仍以 ollama 为主（CPU 环境）；vLLM POC 仅做部署预演，产出供云 GPU 阶段直接复用。

### 2.5 阶段产出

评测方法论、脚本评测框架、Agent 框架 v0、vLLM 部署资产、初步对比报告、Go/No-Go 判定书。

## 3. 阶段二实施方案：云环境搭建 DeepSeek 大模型

### 3.1 云资源与环境

| 步骤 | 操作 |
|------|------|
| 1 | 确定云平台（阿里云百炼 / 腾讯云 / 华为云）并申请 GPU 资源 |
| 2 | 部署 DeepSeek v4 满血推理服务（托管 API 或 vLLM 自建） |
| 3 | 配置 LiteLLM 网关接入云模型（`api_base` 指向云推理） |
| 4 | 建立监控与成本告警 |

### 3.2 脚本评测

- 复用阶段一的题集与打分器，针对 DeepSeek v4 满血执行全量评测。
- 满血模型可扩展**更高难度题集**（长文本、复杂推理、专业翻译）。

### 3.3 Agent 评测（通用 + Smartrans）

- **通用 Agent**：RAG + 工具调用 + 多轮任务集，端到端指标采集。
- **业务场景**：Smartrans 转换精度实测（实际业务题材）。

### 3.4 成本实测

- 按 token、按 GPU 时长、按并发三口径实测，形成成本基线。

### 3.5 阶段产出

DeepSeek v4 单模型评测报告、成本数据、Agent 评测基线、是否扩展多模型的决策建议。

## 4. 阶段三实施方案：多个满血大模型横向对比

### 4.1 多模型环境

- 云上统一接入 DeepSeek v4、Qwen 3.8、GLM 5.3 满血版。
- 经 LiteLLM 网关路由，统一 OpenAI 兼容接口。

### 4.2 统一横向评测

- 相同题集、相同 Agent 任务，三模型并行执行。
- 控制变量：同一套基准、同一环境、同一评测参数。

### 4.3 三维对比与结论

- **性能**：响应延迟、吞吐、并发。
- **质量**：脚本综合分、Agent 任务完成率、人工评分。
- **成本**：每 token 成本、单位任务成本、TCO。

### 4.4 阶段产出

多模型对比矩阵、结论报告（推荐模型 + 部署形态 + 成本）、导入路线图。

## 5. 评测执行要点

评测方法、打分规则、判定基准与测试用例的**详细设计见《05 评测方法及打分规则》**，本节仅列三阶段执行要点：

- **脚本评测**：复用 `scripts/eval/`，按 05 打分规则执行；满血阶段裁判模型升级为云上满血模型，题集分层（基础/进阶）。
- **Agent 评测**：通用 Agent（RAG + 工具 + 多轮）+ Smartrans 业务场景，按 05 任务集与指标采集，关键输出人工双盲评分。
- **判定基准**：阈值（脚本综合分 ≥80、任务完成率 ≥70%、工具调用成功率 ≥85% 等）在阶段一末冻结，详见 05 第 5 节。
- **测试用例**：脚本题集与 Agent 任务集，详见 05 第 6 节。

## 6. 环境方案

### 6.1 本地（阶段一）

- ollama + 6 小模型，CPU 推理。

### 6.2 云（阶段二/三）

| 组件 | 方案 |
|------|------|
| 推理 | 云厂商托管 API 或 vLLM + GPU 实例 |
| 网关 | LiteLLM Proxy（OpenAI 兼容 + 鉴权 + 日志 + 输入/输出护栏） |
| MCP | FastMCP（stdio + HTTP） |
| 监控 | 成本告警 + 用量看板 |

## 7. 成本测算

| 成本项 | 口径 | 说明 |
|--------|------|------|
| API 调用 | 每 token（输入/输出） | 云厂商计费 |
| GPU 实例 | 每实例小时 | 自建推理时 |
| 运维 | 人力 | 环境搭建与维护 |
| 评测 | 裁判模型调用 + 人工评审 | 评测本身成本 |

**TCO = 模型调用 + 基础设施 + 运维 + 评测成本**

**控制措施**：设预算告警、按需伸缩 GPU、非评测时段释放实例。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 云成本超预算 | 预算告警 + 按需伸缩 + 先小规模验证 |
| 满血模型质量不达预期 | 扩大题集/任务集，人工双盲复核 |
| 评测标准化不足 | 冻结基准与题集，统一 LiteLLM 接入 |
| 云平台 API 差异 | LiteLLM 屏蔽差异 |
| 数据合规风险 | 阶段二/三前置合规审查 |
